## 1. Введение

### 1.1 Назначение
MCP-сервер на Python, предоставляющий LLM безопасный доступ к данным 1С УНФ через протокол OData в режиме **readonly**. Сервер абстрагирует LLM от синтаксиса OData, выполняет обработку данных на стороне сервера и кэширует результаты для снижения нагрузки на 1С.

### 1.2 Целевые сценарии
- Аналитика продаж, остатков, взаиморасчетов
- Поиск по справочникам и документам
- Выгрузка агрегированных данных
- Исследование структуры базы данных

### 1.3 Ограничения
- Только чтение (GET-операции OData)
- Целевая система: 1С УНФ (OData)
- Имена сущностей и полей — на кириллице (с алиасами для экономии токенов)

## 2. Архитектура

### 2.1 Компоненты
```
┌──────────┐       ┌─────────────────┐       ┌────────────┐
│   LLM    │◄─────►│   MCP-сервер    │◄─────►│  1С УНФ    │
│ (клиент) │ HTTP  │  (Python)       │ OData │  (OData)   │
└──────────┘       │                 │       └────────────┘
                   │  ┌───────────┐  │
                   │  │  DuckDB   │  │
                   │  │  + Parquet│  │
                   │  │  (кэш)    │  │
                   │  └───────────┘  │
                   │  ┌───────────┐  │
                   │  │ SQLite    │  │
                   │  │ (auth.db) │  │
                   │  └───────────┘  │
                   └─────────────────┘
```

### 2.2 Принцип работы
- **Ленивое чтение**: первый запрос к сущности → выгрузка из 1С → сохранение в Parquet → последующие запросы идут в DuckDB
- **Инкрементальное обновление**: если в сущности есть фильтруемое поле версии/даты — обновляются только измененные записи
- **Полный ресинк**: ночью (03:00) для выявления удаленных записей
- **Принцип «LLM не знает OData»**: LLM оперирует бизнес-сущностями, транспорт — внутри сервера

## 3. Функционал MCP (Tools)

### 3.1 `list_entities`
Возвращает список доступных сущностей с алиасами и описаниями.

**Параметры:** нет  
**Ответ:**
```json
{
  "entities": [
    {"alias": "nomenclature", "name": "Справочник.Номенклатура", "description": "Товары и услуги"},
    {"alias": "sales", "name": "Документ.РеализацияТоваровУслуг", "description": "Продажи"}
  ]
}
```

### 3.2 `get_metadata`
Возвращает структуру полей сущности с алиасами и типами. Технические поля (`Ref_Key`, `DeletionMark`, `IsFolder`) скрыты.

**Параметры:** `entity` (алиас или имя)  
**Ответ:**
```json
{
  "entity": "nomenclature",
  "fields": [
    {"alias": "name", "name": "Наименование", "type": "string"},
    {"alias": "code", "name": "Код", "type": "string"},
    {"alias": "price", "name": "Цена", "type": "decimal"}
  ]
}
```

### 3.3 `fetch_and_process`
Основной инструмент. Выполняет запрос к 1С (или берет из кэша), обрабатывает через pandas/DuckDB, возвращает компактный результат.

**Параметры:**
```json
{
  "entity": "sales",
  "select": ["date", "customer", "sum"],
  "where": [
    {"field": "date", "op": ">=", "value": "2026-01-01"}
  ],
  "group_by": ["customer"],
  "measures": [{"field": "sum", "agg": "sum"}],
  "order_by": [{"field": "sum", "desc": true}],
  "limit": 50
}
```

**Ответ:**
```json
{
  "data": [...],
  "total_count": 1500,
  "truncated": true,
  "message": "Результат обрезан. Уточните фильтр или используйте группировку."
}
```

### 3.4 `refresh_cache`
Принудительное обновление кэша для указанной сущности.

**Параметры:** `entity`, `mode` (`incremental` | `full`)

### 3.5 `lookup`
Поиск по справочникам. Возвращает 5–10 кандидатов с GUID (для внутренних ссылок).

**Параметры:** `entity`, `query`, `fields` (по каким полям искать)

### 3.6 `describe_entity`
Профиль данных: количество записей, диапазон дат, топ значений, доля пустых полей.

### 3.7 `get_last_error`
Детали последней неудачной операции для диагностики.

## 4. Аутентификация и безопасность

### 4.1 Модель доступа
- **1 LLM = 1 токен** (Bearer Token)
- Токены имеют **scope** (allowlist сущностей)
- Токены имеют **срок действия** (`expires_at`)
- Хранение: SQLite (`auth.db`), токены в хэшированном виде (bcrypt)

### 4.2 CLI управления токенами
```bash
mcp-auth create --name "llm_analytics" --scope "nomenclature,sales" --expires 30d
mcp-auth list
mcp-auth revoke <token_id>
mcp-auth cleanup  # удалить просроченные
```

### 4.3 Middleware
При каждом запросе:
1. Проверка токена
2. Проверка scope (доступна ли сущность)
3. Проверка срока действия
4. Логирование: `timestamp`, `token_name`, `entity`, `operation`, `result`

### 4.4 Защита от инъекций
- LLM не формирует OData-запросы напрямую
- Все параметры валидируются по `$metadata`
- HTTP-клиент: только GET, allowlist хоста, запрет редиректов
- Credentials 1С — только из `.env`

## 5. Конфигурация

### 5.1 `config.yaml`
```yaml
odata:
  base_url: "https://1c.example.com/odata"
  allowlist:
    - alias: nomenclature
      name: "Справочник.Номенклатура"
    - alias: sales
      name: "Документ.РеализацияТоваровУслуг"
  field_mapping:
    "Справочник.Номенклатура":
      name: "Наименование"
      code: "Код"

cache:
  storage: "parquet"  # parquet | duckdb
  path: "./cache"
  schedule:
    incremental: "*/15 * * * *"
    full: "0 3 * * *"

limits:
  response_rows: 50
  response_bytes: 10240
  odata_rate: 10  # req/min
  odata_timeout: 30

defaults:
  filter_deletion_mark: true
```

### 5.2 `.env`
```
ODATA_USER=odata_user
ODATA_PASSWORD=secret
AUTH_DB_PATH=./auth.db
```

## 6. Обработка ошибок

### 6.1 Формат ошибок
```json
{
  "error": {
    "code": "FIELD_NOT_FOUND",
    "message": "Поле 'cost' не найдено в сущности 'nomenclature'",
    "hint": "Доступные поля: name, code, price",
    "recoverable": true
  }
}
```

### 6.2 Circuit Breaker
- При 3 подряд ошибках к 1С → блокировка прямых запросов на 5 минут
- В это время работают только запросы к кэшу

### 6.3 Лимиты выдачи
- Максимум 50 строк / ~10 КБ на ответ
- При превышении: `truncated: true` + `total_count` + подсказка

## 7. Оптимизация

### 7.1 Кэш
- **Хранилище**: Parquet-файлы (по одному на сущность) + DuckDB для запросов
- **Индексы DuckDB**: автоматическое создание на полях частых фильтров (Дата, Код, Наименование)
- **Разрешение ссылок**: LLM пишет `где Номенклатура = "Бумага А4"` → сервер находит GUID в кэше → подставляет в `$filter` → в ответе `$expand` обратно в Наименование

### 7.2 Лимиты
| Контур | Ограничение |
|---|---|
| Upstream (1С) | 5–10 req/min, concurrency 1–2, timeout 30–60 с, retry + backoff, circuit breaker |
| Local (кэш) | Лимит строк / объёма / времени вычисления |

### 7.3 Автофильтр
`ПометкаУдаления = Ложь` применяется автоматически ко всем запросам.
